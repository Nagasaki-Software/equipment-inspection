# 点検結果PDF 特記事項ページと様式の並び順 設計書

**作成日:** 2026-08-31
**状態:** 未承認
**前提:** `2026-08-31-form-shared-judgment-design.md` の実装完了後（ブランチ `feature/layout-ui`）

## 目的

点検結果のPDFを、綴じてそのまま使える並びにする。

- **特記事項を1枚目にする。**いまは機器ごとの表の中に埋もれていて、月に何があったかを一目で追えない
- **様式PDFの並び順を指定できるようにする。**いまはフォルダ名順で、綴じたい順と一致しない

## いまの並び（変更前）

```
 様式PDF          … forms_layout.list_forms() の順＝フォルダ名順
 表出力            … 使用前点検（機器ごとに1枚） → 月例点検（大分類ごとに1枚）
```

**特記事項は独立したページではない。**次の2か所に、行として埋め込まれている。

| 場所 | 見え方 |
|---|---|
| 使用前点検の表（機器ごと） | 最下段の「備考」行に `2026/8/3　異音あり` を改行で並べる |
| 月例点検の表（大分類ごと） | 「特記事項」行に `クレーン1　内容` を改行で並べる |

## 決めたこと

| 論点 | 決定 |
|---|---|
| 並べ替える単位 | **様式だけ。**特記事項は先頭固定、表出力は最後に固定 |
| 特記事項ページを出すタイミング | **常に先頭に出す。**1件も無い月は「特記事項なし」と印字する |
| 特記事項ページの中身 | **機器ごとにまとめる**（機器の中は点検日順） |
| 並び順の指定方法 | 設定画面で、**各行の ▲▼ ボタン**で入れ替える |

---

## 1. PDFの並び（変更後）

```
 1枚目      特記事項        ← 新規。常に先頭
 2枚目〜    様式PDF         ← config.json の form_order 順（未設定ならフォルダ名順）
 最後       表出力          ← 従来どおり
```

## 2. 特記事項ページ

### 体裁

既存の表出力に合わせる。**別の見た目にしない。**

- A4横（`landscape(A4)`）、`SimpleDocTemplate`
- タイトル：`（建物名）　2026年8月　特記事項`（`styles["title"]` を使う）
- 表の文字は `styles["jp"]`、内容の欄は `styles["remark"]`

### 中身

**機器／点検日／種別／内容** の4列。

| 列 | 内容 |
|---|---|
| 機器 | `category_minor`。同じ機器が続く行はまとめて1回だけ出す（縦結合） |
| 点検日 | `2026/8/3` の形 |
| 種別 | `使用前` / `月例`。**同じ機器に両方の記録があると、日付だけでは見分けられないため足す** |
| 内容 | `general_remark` の本文 |

### 並び順

1. **機器の順は点検項目マスタ（`data/equipment_master.csv`）の並び順。**`_generate_pdf` が `categories` を作るときと同じ順にする（表出力とページの順が食い違わないため）
2. 同じ機器の中は**点検日の古い順**
3. 同じ機器・同じ日に使用前と月例の両方があれば、**使用前 → 月例**の順

マスタに無い機器の記録は、**マスタにある機器をすべて出したあと、機器名の五十音（文字コード）順**で末尾に足す。記録があるのに1枚目から消えるほうが困るため。

### データの集め方

表出力と**同じ範囲**にする。ずれると「表には出ているのに1枚目に無い」が起きる。

| 種別 | 読むファイル | 絞り込み |
|---|---|---|
| 使用前 | `get_result_file_path("使用前", …)` を**サイクル開始月と表示月の2つ** | `inspection_date` が `get_cycle_range()` の範囲内のものだけ |
| 月例 | `get_result_file_path("月例", 表示年, 表示月)` | 絞り込みなし（表出力と同じ） |

`general_remark` が空文字・空白のみ・文字列でないものは、その行を作らない。

### 1件も無いとき

ページは出す。表の代わりに **「特記事項なし」** の1行を印字する。

## 3. 様式の並び順

### config.json

```json
"form_order": ["form_02", "form_01"]
```

様式ID（フォルダ名）の配列。**既定は空配列**（キーが無い場合も空として扱う）。

### 並べ替えの規則

| 状況 | どうなるか |
|---|---|
| `form_order` が空・未設定 | **フォルダ名順。今と1文字も変わらない** |
| `form_order` に無い様式がある | 指定した様式の**あと**に、フォルダ名順で続ける（新しく作った様式が消えない） |
| `form_order` にあるが実在しない | 無視する（削除済みの様式IDが残っていても壊れない） |
| `form_order` に同じIDが2回ある | 最初の1回だけ有効。2回目以降は無視する |

並べ替えは `_build_form_writers()` の中で、`list_forms()` の結果に対して行う。
**出力に失敗して表出力に落ちた様式（`fallbacks`）の扱いは変えない。**

### `api_post_config` の検証

このAPIはキーごとに検証して取り込む作りなので、`form_order` の分岐を足す。**足さないと画面から保存しても無視される。**

```python
    if "form_order" in data:
        fo = data["form_order"]
        if not isinstance(fo, list):
            return jsonify({"error": "form_order は配列で指定してください"}), 400
        if len(fo) > 200:
            return jsonify({"error": "form_order が長すぎます"}), 400
        for name in fo:
            if not isinstance(name, str):
                return jsonify({"error": "form_order は様式IDの配列で指定してください"}), 400
        config["form_order"] = fo
```

## 4. 設定画面（機器点検の設定）

「様式の割り当て」の**下**に「様式の並び順」を足す。

```
 様式の並び順
 ┌────────────────────────────────────┐
 │ クレーン複数日常点検（form_01）      ▲ ▼ │
 │ クレーン日常点検（form_02）          ▲ ▼ │
 │ 確認用 日常点検表（sample_daily）    ▲ ▼ │
 └────────────────────────────────────┘
 上から順にPDFに綴じられます。特記事項は常に1枚目、表出力は常に最後です。
```

- 一覧は `/api/forms` から作る（`id` と `form_name`）
- 並びは `config.form_order` を上の規則で適用したもの。**画面に出る順が、そのままPDFの順**
- **いちばん上の行の ▲ と、いちばん下の行の ▼ は押せない**（`disabled`）
- 押すとその場で行が入れ替わる。保存は既存の「設定を保存」ボタンに相乗りする
- `handleSettingsSave()` の `payload` に `form_order` を足す。**画面に出ている順のIDの配列**を送る
- 様式が0件のときは「様式がありません」と出す

## 実装で間違えやすいところ

- **様式が1つも無いときの分岐。**`api_get_pdf` には「様式が1つも無ければ表出力をそのまま返す」早期returnがある。**ここを直し忘れると、様式を作っていない環境では特記事項ページが出ない。**両方の道で先頭に足すこと
- **使用前の記録は、サイクル外の日も同じ月のファイルに入っている。**日付でサイクル内に絞らないと、前月・翌月の特記事項が混じる
- **`equipment_name` は大分類が入っている。**機器名として使うのは `category_minor`
- **表出力（`_generate_pdf`）には手を入れない。**特記事項ページは別のPDFとして作り、合成のときに先頭へ足す。こうすれば既存の出力は1バイトも変わらない
- 版数（`app.js?v=`）は `inspection.html` の1か所。上げ忘れると利用者のブラウザが古い設定画面を使い続ける

## 変えないもの

- 表出力の中身と見た目（機器ごとの備考行も**そのまま残す**）
- 点検画面・保存されるJSON・CSV・様式レイアウト画面
- ポート5000・締め日区切り・`utf-8-sig`

## 対象外（今回やらないこと）

- 表出力（使用前の機器ごと・月例の大分類ごと）の並べ替え
- 特記事項ページの体裁の指定（文字サイズ・列幅などの設定項目）
- 機器ごとの表から備考行を省く選択肢
- 特記事項ページを出す・出さないの切り替え（常に出す）
- 特記事項をCSVに出すときの並び

## 検証方法

### pytest（追加するテスト）

**様式の並び順**

1. `form_order` が未設定なら、様式がフォルダ名順に並ぶ（現状維持）
2. `form_order` で指定した順に並ぶ
3. `form_order` に無い様式が、指定した様式のあとにフォルダ名順で続く
4. `form_order` に実在しない様式IDが混じっていても落ちない
5. `form_order` に同じIDが2回あっても、その様式が2回出ない
6. `api_post_config` が `form_order` を保存する／配列でなければ400を返す

**特記事項ページ**

7. 1枚目に「特記事項」の見出しがある
8. 機器ごとにまとまり、同じ機器の中は日付順に並ぶ
9. 使用前と月例の両方が1枚に出る。種別の列で見分けられる
10. サイクル外の日の記録が混じらない
11. 記録が1件も無い月は「特記事項なし」と出る
12. **様式が1つも無い環境でも、1枚目が特記事項になる**
13. **既存の表出力の中身が変わらない**（変更前のコードと出力を突き合わせる）

### 実機（テストだけでは足りない）

- 設定画面で ▲▼ を押して並べ替え、保存して開き直しても順が保たれること
- **PDFを実際に開いて、1枚目が特記事項・2枚目以降が指定した様式の順であることを目で見る**
- 特記事項を書いていない月でもPDFが出て、1枚目に「特記事項なし」と出ること
