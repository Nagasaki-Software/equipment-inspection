# 点検結果の様式PDF出力 — 設計書

作成日: 2026-08-22
対象アプリ: equipment-inspection（このリポジトリ）
状態: **承認済み**（2026-08-22 ユーザー承認）

## 1. 目的

点検結果を、現場で使っている既存の紙の様式（PDF化したもの）にそのまま印字できるようにする。
様式を用意しない機器は、これまでどおり表形式のPDFで出力する。

## 2. 背景

現行アプリは、点検結果を月単位で集計し、アプリが組み立てた表形式のPDFとして出力する。
しかし提出・保管に使う様式は機器ごとに決まっており、表形式では代用できない。
参照実装として、作者の別の自作アプリ（非公開）に、reportlab + pypdf で様式へ重ね書きする仕組みがある。

## 3. 決定事項

| # | 論点 | 決定 |
|---|---|---|
| 1 | 記録する内容 | ○ / × / ー の判定 **＋ 数値** |
| 2 | 数値の上下限判定・NG色分け | **作らない**（数値を記録・印字するだけ） |
| 3 | メーター累計からの使用量自動計算・計算式 | **作らない** |
| 4 | 様式PDFを使うかの選択単位 | **小分類（機器）ごと** |
| 5 | 座標の決め方 | **アプリ内に配置画面を作る** |
| 6 | 出力タイミング | **既存の「PDF出力」ボタンで月単位に一括** |
| 7 | 実装方式 | 様式フォルダ方式 ＋ 既存 PDF.js を配置画面に流用 |
| 8 | 追加パッケージ | **pypdf のみ**（着手前にスキャンと承認を得る） |
| 9 | 入力デバイス | タッチとマウス・キーボードの**両方**を想定 |
| 10 | 既存データの移行 | **不要**（結果ファイルの構造を変えない） |
| 11 | `month` 型の軸の単位 | **サイクル内の通し番号**（1番目＝締め日の翌日。1日始まりではない） |
| 12 | 余ったマス（該当日なし） | **「ー」を印字**（記入漏れの空欄と見分けるため） |
| 13 | 締め日（現在24日固定） | **`config.json` に出す**（既定24。現在の動作は変えない） |
| 14 | 様式の日にち欄 | **ブランクにしてアプリが印字**。土曜は青丸、日曜・祝日・会社休業日は赤丸で囲む |
| 15 | 様式のタイトルの月 | **ブランク（〇月）にしてアプリが数字を書き込む**。様式の毎月差し替えを不要にする |
| 16 | 数値項目の「点検対象外」 | **判定項目と同じ「ー」を使う**（数値欄の横に「ー」ボタンを置く） |
| 17 | 点検項目の識別 | **`category_major` + `category_minor` + `inspection_item` の3つ**。項目名だけでは機器を区別できない |

## 4. 用語

- **様式** — 現場の紙の点検表をPDF化したもの。`form.pdf`。
- **配置** — 様式PDF上のどの座標に、どの点検項目の結果を印字するかの定義。
- **軸** — 様式上で等間隔に並ぶ欄の列（1年分様式なら月の列、1か月分様式なら日の列）。
- **機器** — 点検項目マスタの `category_minor`（小分類）。様式の紐づけ単位。

## 5. 様式の型

| 型 | 意味 | 1欄の単位 | 欄数の既定 |
|---|---|---|---|
| `year` | 1枚に1年分 | 1か月 | 12 |
| `month` | 1枚に1サイクル分 | 1日 | 31 |
| `single` | 1回の点検で1枚 | （軸なし） | — |

`month` の「1サイクル」は締め日で区切られた期間（前月24日〜当月23日）で、日数は28〜31日と月ごとに変わる。詳細は6.4・6.5を参照。

いずれの型でも、1つの様式に複数の機器を紐づけられる（例: 吊具A・B・Cが1枚に載る）。

## 6. データ設計

### 6.1 フォルダ構成

```
equipment-inspection/
├─ forms/                    ← 新規。設定で別パスに変更可
│   ├─ crane1/
│   │   ├─ form.pdf
│   │   └─ layout.json
│   └─ tsurigu/
│       ├─ form.pdf
│       └─ layout.json
```

様式フォルダの場所は `config.json` の `forms_directory` で指定する。空欄ならアプリ内の `forms/` を使う（`save_directory` と同じ考え方）。

フォルダ名（様式ID）は半角英数字とアンダースコアのみ。日本語の様式名は `layout.json` の `form_name` に持つ。

### 6.2 layout.json

```json
{
  "form_name": "吊具月例点検表",
  "period": "year",
  "inspection_type": "月例",
  "targets": ["吊具A", "吊具B", "吊具C"],
  "axis": {
    "step_x": 38.0,
    "step_y": 0.0,
    "count": 12
  },
  "default_font_size": 11,
  "fields": [
    {
      "source": "meta.building_name",
      "page": 0, "x": 90.0, "y": 780.0,
      "font_size": 11, "color": "#000000"
    },
    {
      "source": "item:吊具A|傷はないか",
      "page": 0, "x": 120.0, "y": 660.0,
      "on_axis": true,
      "font_size": 11, "color": "#000000",
      "mark_ok": "○", "mark_ng": "×", "mark_na": "ー"
    },
    {
      "source": "item:吊具A|油圧",
      "page": 0, "x": 120.0, "y": 630.0,
      "on_axis": true,
      "font_size": 11, "color": "#000000"
    }
  ]
}
```

**トップレベルのキー**

| キー | 必須 | 内容 |
|---|---|---|
| `form_name` | ○ | 様式の表示名（日本語可） |
| `period` | ○ | 様式の型（`year` / `month` / `single`） |
| `inspection_type` | ○ | この様式が対象とする点検種別（`使用前` / `月例`）。結果を取り出すときの絞り込みに使う |
| `targets` | ○ | この様式に載る機器（`category_minor`）の一覧 |
| `axis` | — | 軸の定義。`period` が `year` / `month` のときのみ |
| `default_font_size` | — | 省略時 11 |
| `fields` | ○ | 配置の一覧 |

**フィールドの意味**

| キー | 必須 | 内容 |
|---|---|---|
| `source` | ○ | 印字する内容の指定（6.3参照） |
| `page` | ○ | 様式PDFのページ番号（0始まり） |
| `x`, `y` | ○ | 印字位置。PDF座標（左下が原点、単位はポイント） |
| `on_axis` | — | `true` なら軸に沿って繰り返す。既定 `false` |
| `font_size` | — | 省略時は `default_font_size` |
| `color` | — | 省略時は `#000000`。`meta.day` では平日の色として使う |
| `mark_ok` / `mark_ng` / `mark_na` | — | 判定項目で ○ / × / ー の代わりに印字する文字。省略時はそのまま ○ / × / ー |
| `circle_radius` | — | `meta.day` のみ。休日を囲む丸の半径。省略時は `font_size × 0.9` |

`mark_na` は、**数値項目であっても「該当日なしの余りマス」に印字する文字として使う**（6.4参照）。数値項目で `mark_na` を省略した場合も既定は「ー」。

`axis` は `period` が `year` / `month` のときのみ持つ。`single` のときは `axis` を持たず、`on_axis: true` は指定できない（指定されていた場合は無視してログに記録する）。

### 6.3 source の書式

| 書式 | 印字される内容 |
|---|---|
| `meta.inspection_date` | 点検日（`YYYY/MM/DD`） |
| `meta.inspector` | 点検者名 |
| `meta.department` | 所属 |
| `meta.building_name` | 建物名 |
| `meta.general_remark` | 備考（機器単位の全体備考） |
| `meta.year` | 対象年（4桁）。タイトルの「〇年」のブランクに置く |
| `meta.month` | 対象月（1〜12）。タイトルの「〇月」のブランクに置く |
| `meta.day` | その欄の日にち（数字のみ）。土日祝は丸で囲む（6.6参照）。`on_axis: true` で使う |
| `item:<機器名>\|<点検項目名>` | その項目の結果（判定文字または数値） |
| `remark:<機器名>\|<点検項目名>` | その項目の備考 |

`<機器名>` は点検項目マスタの `category_minor` と一致させる。

`meta.*` のうち `inspection_date` / `inspector` / `department` / `general_remark` は、`on_axis: true` を付ければ軸に沿って欄ごとに印字できる（例: 各月の点検者名を12欄に並べる）。

### 6.4 座標の計算

`on_axis: true` のフィールドについて、軸の n 番目（n は 1 始まり）の印字位置は次で求める。

```
印字x = x + step_x × (n - 1)
印字y = y + step_y × (n - 1)
```

`x`, `y` は「1番目の欄における位置」。横並びの様式は `step_y = 0`、縦並びの様式は `step_x = 0` になる。斜めや両方0以外も式としては成立する。

n の対応は次のとおり。

- `period: "year"` — n = 対象年の月（1〜12）
- `period: "month"` — n = **点検サイクル内の通し番号**（1番目 = サイクル開始日）

**`month` 型は「1日始まり」ではない。** このアプリの日常点検は締め日で区切られており、対象月 M のサイクルは「前月24日 〜 当月23日」である（6.5参照）。したがって n=1 は前月24日、n=2 は前月25日…となる。

サイクルの日数は月によって 28〜31日と変わる（うるう年は29日）。

| 例（2026年） | 期間 | 日数 | 31マス様式の余り |
|---|---|---|---|
| 3月分 | 2/24 〜 3/23 | 28日 | 3マス |
| 5月分 | 4/24 〜 5/23 | 30日 | 1マス |
| 9月分 | 8/24 〜 9/23 | 31日 | 0マス |

**余ったマスの扱い**

n がサイクルの実日数を超える欄（＝その月には存在しない日）には、`item:` のフィールドに限り `mark_na`（既定「ー」）を印字する。`remark:` と `meta.*` は空欄のままにする。

これにより、**「該当日なし」と「点検の記入漏れ」を見分けられる**。

| 状態 | 印字 |
|---|---|
| その日に点検した | 結果（○ / × / ー / 数値） |
| その日は点検していない（記入漏れ・休日など） | **空欄** |
| その月にはその日が存在しない（余りマス） | **ー** |

`n > axis.count` になる欄は印字しない（例: `count: 12` の様式に13番目は無い）。

### 6.5 点検サイクルの締め日

日常点検（使用前点検）の集計期間は「前月24日 〜 当月23日」である。現在この `24` は `app.py:687` と `static/app.js:69` の2か所に直接書かれている。

様式PDFの座標計算でも同じ値が必要になるため、**`config.json` の `cycle_start_day` に出して1か所にまとめる**（既定値 24。現在の動作は変わらない）。サーバ側は `load_config()` から、画面側は `/api/config` から読む。

月例点検はこの締め日の影響を受けない（月単位の記録として保存されるため、`year` 型の n はそのまま対象年の月に対応する）。

### 6.6 日にちの印字と休日の色分け

**様式の日にち欄はブランクにしておき、アプリが日にちを書き込む。** これにより、1つの様式を毎月使い回せる。

`meta.day` を `on_axis: true` で配置すると、各欄にその日の日にち（数字のみ）を印字する。サイクルは前月24日始まりのため、印字される数字は 24, 25 … 31, 1, 2 … 23 のように月をまたぐ。

**休日の色分け**

| その日 | 数字の色 | 丸 |
|---|---|---|
| 平日 | 黒（`color` で変更可） | なし |
| 土曜 | 青 `#0000ff` | **青い丸で囲む** |
| 日曜・祝日・会社の休業日 | 赤 `#ff0000` | **赤い丸で囲む** |

判定は既存の `get_holiday_info()` をそのまま使う（祝日は `jpholiday`、会社の休業日は `data/custom_holidays.csv`）。

**土曜と祝日が重なった日は赤**にする（赤の条件が1つでも当てはまれば赤が優先）。

**座標の扱い**: `meta.day` のフィールドでは `x`, `y` は**丸の中心**を指す。数字は中心に揃えて描く（他のフィールドは左下基準）。

**丸の大きさ**: `circle_radius` で指定する。省略時は `font_size × 0.9`。欄の大きさは様式ごとに違うため、レイアウト画面で数値を調整し、試し刷りで確認する。

余りマス（そのサイクルに存在しない日）には日にちも丸も印字しない（`item:` の「ー」だけが入る）。

**タイトルの月**

タイトルも「**〇月 日常点検結果**」のように月をブランクにしておき、`meta.month` を〇の位置に配置する。1年分の様式（`year` 型）は `meta.year` を使う。これで、月が変わるたびに様式を差し替える必要がなくなる。

### 6.7 点検項目マスタの列追加

`data/equipment_master.csv` に2列を追加する。

```csv
category_major,category_minor,inspection_item,inspection_type,input_type,unit
クレーン,クレーン1,点検項目C-1,月例,判定,
クレーン,クレーン1,油圧,月例,数値,MPa
```

列名は既存の見出し行に合わせて半角英字にする（値は日本語のまま）。

- `input_type`（入力方式）— `判定`（既定）または `数値`
- `unit`（単位）— `数値` のときのみ意味を持つ。入力画面と表PDFに表示する。**様式PDFには印字しない**（単位は様式に印刷済みのため）

**後方互換**: 2列が存在しない、または空欄の行は `判定` / 単位なし として読む。現在の `equipment_master.csv` は変更なしで動作する。

### 6.8 点検結果ファイル

`results/<YYYY-MM>/*.json` の構造は**変更しない**。

```json
{ "equipment_name": "吊具A", "inspection_item": "油圧", "result": "0.52", "remark": "" }
```

`result` に判定文字（`○`/`×`/`ー`）または数値の文字列が入る。単位は入れない（マスタから引く）。既存の記録はそのまま読める。

**サーバ側の処理**（`_validate_results` と保存処理）に次を追加する。

1. 全角数字・全角ピリオド・全角マイナスを半角に正規化してから保存する（画面側の変換が効かなかった場合の保険）
2. 正規化後の値が数値として解釈できなければ 400 を返す

画面側でも同じ正規化を行うが（7.2 改善案6）、**保存される値の正しさはサーバ側で担保する**。

**数値項目の判定で守るべきこと**（実装時のレビューで判明した落とし穴）

| 落とし穴 | 対策 |
|---|---|
| 同じ点検項目名が複数の機器に存在する（現行マスタに実在） | 数値項目の判定は **`category_major` + `category_minor` + `inspection_item` の3つ**で絞る。項目名だけで判定すると、別の機器の判定項目まで数値扱いになり、その機器の点検結果が一切保存できなくなる |
| 長音「ー」を半角マイナスに正規化すると対象外の記録が壊れる | 「ー」は変換対象から外す。値がちょうど「ー」なら数値検証を通す |
| `float()` での判定は `inf` / `nan` / `1e5` / `1_000` を通す | 正規表現 `^[+-]?(\d+(\.\d*)?\|\.\d+)$` で判定する |
| マスタCSVが cp932 で保存されると保存APIごと 500 になる | マスタ読み込みを try/except で囲み、読めなければ数値検証を省略して従来どおり保存できるようにする |
| `result` が JSON の数値型で送られると弾かれる | 正規化時に数値型を文字列へ変換する |

## 7. 画面設計

### 7.1 様式レイアウト画面（新規 `/layout`）

点検画面のサイドバーに「様式レイアウト」ボタンを追加して開く。**管理者操作扱い**（既存の `require_admin` を適用。localhost または管理者キー）。

```
┌─────────────────────────────────────────────────────────────┐
│ 様式：[ 吊具月例点検表 ▼ ] [新しい様式を追加] [試し刷り] [保存] │
├──────────────┬──────────────────────────┬───────────────────┤
│ 配置する項目  │                          │ 選択中の設定       │
│ ▸ 共通       │   様式PDFを PDF.js で     │ 文字サイズ 11      │
│  ・点検日 ✓  │   表示（クリックで配置）   │ 色  ■黒            │
│  ・点検者    │                          │ ○の記号 [○]       │
│ ▸ 吊具A      │                          │ 軸に沿う ☑         │
│  ・傷 ✓      │                          │ 丸の半径 10.0      │
│  ・油圧      │                          │ [配置を削除]       │
│              │                          │ [下へ複製...]      │
├──────────────┴──────────────────────────┴───────────────────┤
│ 軸：[1つ目の欄を指定] [2つ目の欄を指定] ズレ 38.0 欄数[12]      │
└─────────────────────────────────────────────────────────────┘
```

**操作**

1. 左の一覧から項目を選ぶ
2. 中央の様式PDF上をクリックすると、その位置に配置される
3. 配置済みの項目には ✓ が付く
4. 配置した印はドラッグで移動、**矢印キーで1ポイントずつ微調整**（改善案3）
5. 「保存」で `layout.json` に書き出す

**軸の設定**は、1番目の欄を1回クリック、2番目の欄をもう1回クリックする。`step_x` / `step_y` は2点の差から自動計算する。欄数は手入力。

**新しい様式の追加**

1. 様式名（日本語可）と様式ID（半角英数）を入力
2. 様式PDFファイルを選択してアップロード → `forms/<様式ID>/form.pdf` に保存
3. この様式に載る機器をチェックで選ぶ（複数可）
4. 型（`year` / `month` / `single`）を選ぶ
5. 配置して保存

**改善案の反映**

- **1. 試し刷り**（`GET /api/forms/<id>/preview`）— サンプル値を入れた様式PDFをその場で生成して開く。判定項目は ○、数値項目は `0.00`、日付は当日、点検者は「見本 太郎」。軸のある様式は全欄を埋める。**日にちと土日祝の丸も実際と同じように描く**ので、丸の大きさと位置をこの画面で確認できる。試し刷りの対象月は画面で選べるようにする（日数が28日の月と31日の月の両方を確認できるようにするため）。
- **2. 配置のまるごと複製** — 機器を1つ選び、「その機器の配置一式を、指定した機器へ、X方向 dx・Y方向 dy ずらして複製」する。項目名の対応は点検項目名の一致で取る。一致しない項目は複製せず、件数を画面に表示する。
- **4. 保存時の未配置チェック** — 配置されていない項目があれば「配置していない項目が N 件あります。このまま保存しますか？」と確認する。強制はしない。

### 7.2 点検入力画面（既存 `/inspection`）の変更

変更は数値項目の入力方法のみ。判定項目は現状のまま（○×ーボタン、備考、「全て○」、数字キーのショートカット、×があるときの警告）。

- **数値項目**: ○×ーボタンの代わりに数値入力欄を表示し、右に単位を添える。あわせて**「ー」ボタンを1つ置く**（その日は点検対象外、という記録。押すと入力欄に「ー」が入る）
- **改善案5. 前回値の表示** — 数値入力欄の下に「前回 0.52 MPa」を薄く表示する。前回値は、同じ機器・同じ点検項目で、今回の対象日より前の直近の記録から引く（同月内に無ければ前月以前も遡る。上限3か月分まで遡り、無ければ非表示）
- **改善案6. 全角数字の自動変換** — 入力欄からフォーカスが外れた時点で、全角数字・全角ピリオド・全角マイナスを半角に変換する
- **改善案8. 画面上テンキー** — 数値入力欄をタップ/クリックしたときに、0〜9・小数点・マイナス・BS・確定のボタンを入力欄の直下に表示する。物理キーボードからの入力も同時に受け付ける

**未入力チェック**: 既存の「全て点検されていません」の判定に数値項目も含める（空欄は未入力扱い）。

## 9. PDF出力の流れ

`GET /api/pdf?display_year=YYYY&display_month=MM` の処理を次のように拡張する。

1. 対象月の点検結果を読む（既存処理）
2. すべての `layout.json` を読み、`targets` に載っている機器の集合を作る
3. 機器を **様式組** と **表組** に分ける
4. 様式組: 様式ごとに、型に応じた期間の結果を集めて印字ページを作る
   - `year` — 対象月が属する年の1〜12月。各月は**その月の月例点検の最新記録**を使う
   - `month` — 対象月の点検サイクル（前月24日〜当月23日、6.5参照）。各日はその日の記録を使う。サイクルの実日数を超える欄には「ー」を印字する
   - `single` — 対象月に点検日が N 日あれば N 枚（様式PDFを N 回複製する）
5. 表組: 既存の `_generate_pdf` と同じ表を作る
6. すべてを1つのPDFに結合して返す（並び順: 様式組 → 表組）

**重ね書きの手順**: reportlab で様式と同じページサイズの透明なページに文字だけを描き、pypdf の `merge_page` で `form.pdf` の各ページに重ねる。様式PDF自体は書き換えない。

**フォント**: 既存の `register_jp_font()` が登録している日本語フォントをそのまま使う。新たなフォント登録は行わない。

**`single` 型の複製**: 様式PDF全体（複数ページならその全ページ）を点検日の数だけ複製し、それぞれに1日分を印字する。

排他制御は既存の `_pdf_lock` をそのまま使う。

## 10. エラー処理

| 事象 | 動作 |
|---|---|
| 様式PDFが見つからない | その様式の対象機器を**表出力に切り替える**。ログに WARNING。レスポンスヘッダ `X-Form-Fallback` に様式IDを入れ、画面に「一部を表で出力しました」と表示 |
| 様式PDFが壊れている（pypdf が読めない） | 同上 |
| `layout.json` が壊れている（JSON parse 失敗） | 同上。加えて起動時とレイアウト画面で該当様式を「設定エラー」と表示 |
| `page` が様式のページ数を超える | そのフィールドだけ飛ばし、ログに WARNING |
| `source` がマスタに無い項目を指す | そのフィールドだけ飛ばし、ログに WARNING（マスタから項目を消した場合に起きる） |
| 同じ機器が複数の様式に紐づいている | すべての様式に印字する（重複を禁止しない）。レイアウト画面の割り当て一覧で警告表示 |
| 対象期間に結果が1件も無い（`year` / `month`） | 様式は白紙のまま出力する（様式そのものは出す） |
| 対象月に点検日が1日も無い（`single`） | その様式は**出力しない**（0枚。白紙を何枚出すか決められないため） |

`layout.json` の保存は、既存の結果ファイルと同じ方式にする。`filelock` で排他、`_backup_file` で世代バックアップ、一時ファイル + `os.replace` でアトミック書き込み。

## 14. 座標変換

レイアウト画面で様式PDF上をクリックしたときの画面座標は、PDF.js の `viewport.convertToPdfPoint(x, y)` でPDF座標に変換する。表示倍率を変えても同じPDF座標が得られるため、倍率を固定する必要はない。

逆に、保存済みの配置を画面に表示するときは `viewport.convertToViewportPoint(x, y)` を使う。
