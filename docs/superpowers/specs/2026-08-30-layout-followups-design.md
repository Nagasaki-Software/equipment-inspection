**作成日:** 2026-08-30

## 目的

様式レイアウト画面を実際に使うにあたって出てきた、4つの不足を埋める。

| | 要望 | いまの状態 |
|---|---|---|
| ① | ズレ x / y を手入力できるように | クリックでしか決められず、表示は読み取り専用 |
| ② | 点検者名を横書き／縦書きから選べるように | `drawString` で横書き固定 |
| ③ | 壊れた様式・不要な様式をアプリから削除できるように | 削除の手段が無い（フォルダを手で消すしかない） |
| ④ | 1日のマスの位置に実施月を表示できるように | 月の変わり目が紙の上で分からない |

## ① ズレ x / y の手入力

### 画面

下部バーの読み取り専用の表示を、入力欄に置き換える。

```
並び方： [1つ目のマスを指定] [2つ目のマスを指定]   ズレ x [ 23.0 ] y [ 0.0 ] pt（≒8.1mm）   マスの数 [ 31 ]
```

- 2か所をクリックすると、これまでどおり値が入る
- 直接打ち直すと、**その場で薄い文字の並びが描き直される**
- `step="0.1"`。負の数も入れられる（下や左に並ぶ様式のため）
- 単位はPDFの点（pt）。`1pt = 0.3528mm` で換算した値を隣に添える（小数1桁）

### 変更するもの

- `static/layout.html` … `#axis-step`（`<span>`）を `#axis-step-x` `#axis-step-y` の `<input type="number">` と `#axis-step-mm`（換算の表示）に置き換える
- `static/layout.js` … `updateAxisLabel()` が入力欄に値を入れる形に変わる。`change` で `layout.axis` を更新して `renderMarkers()` を呼ぶ
- `handleAxisPick()` は、値を決めたあと `updateAxisLabel()` を呼んで入力欄に反映する

### 決めたこと

- **ミリ単位での入力はしない。**保存される値はptで、クリックで得られる値もptなので、入力もptに揃える。ミリは参考表示のみ
- 空欄にしたら0として扱う（「指定していない」状態に戻す手段は、もう一度クリックで指定し直すこと）

## ② 縦書き

### 画面

右パネル（配置を1つ選んだときの設定）に、チェックボックスを1つ足す。

```
フォルダ名  form_01
項目        点検者名
ページ      1
X / Y / 文字サイズ / 色
□ 縦書きにする          ← 追加
☑ マスの数だけ繰り返す
```

- **点検者名だけでなく、文字を書くどの項目でも選べる。**点検者名だけ特別扱いするより実装が単純になるため
- 「日にち（土日祝は丸）」だけは対象外（1文字を丸の中央に置く項目なので縦書きの意味がない）。この項目を選んだときはチェックボックスを出さない

### 印字（`pdf_forms._draw_field`）

`field.vertical` が真のとき、1文字ずつ下に積んで描く。

```python
    if field.get("vertical"):
        # 1文字ずつ下に積む。PDFのYは上が正なので、下へは減らす。
        for i, ch in enumerate(text):
            c.drawString(x, y - size * i, ch)
        return
```

- 行間は文字サイズと同じ（日本語は正方形に近いため）
- クリックした位置は**1文字目の左下**（横書きと同じ基準）

### プレビュー（`layout-preview.js`）

CSS の `writing-mode: vertical-rl` で縦書きにする。上端の基準を横書きと合わせるため、縦書きのときは `top` のずらし（`vy - size * 0.8`）をやめ、`vy - size` にする。

### `layout.json`

`fields[]` の要素に `"vertical": true` が増える。**既存の様式は `vertical` を持たないので、これまでどおり横書きになる。**

## ③ 様式の削除

### 方針：完全には消さず、ゴミ箱に移す

```
（様式フォルダ）/.trash/form_01_20260830_143022/
```

理由は2つ。

- **様式PDFは、紙を取り込んだ唯一の控えである場合がある。**誤って消すと戻せない
- このアプリは `layout.json` も設定も10世代のバックアップを残す作りになっている。削除だけ非可逆なのは一貫しない

ゴミ箱から戻すのは、フォルダを `.trash` の外に移して名前から日時を取るだけ。手順は `CLAUDE.md` に書く。

### API

```
DELETE /api/forms/<form_id>     @require_admin
```

| 応答 | 条件 |
|---|---|
| 200 `{"status":"ok","moved_to":"..."}` | 移動できた |
| 400 | `form_id` が安全でない（後述） |
| 404 | その名前のフォルダが無い |
| 500 | 移動に失敗した（ファイルが使用中など） |

### 「安全でない」の判定

**削除は、レイアウト画面で開けない様式にも効く必要がある**（それが主目的）。そのため `is_valid_form_id()` は使わない。日本語名のフォルダも削除できないと困る。

代わりに次を満たすものだけ受け付ける。

- `/` `\` を含まない
- `.` `..` そのものでない
- 先頭が `.` でない（ゴミ箱そのものを消させない）
- 解決したパスの親が、様式フォルダそのものである（`Path.resolve()` で比較。シンボリックリンク経由の脱出を防ぐ）

### 一覧からの除外（`forms_layout.list_forms`）

**先頭が `.` のフォルダを一覧に出さない。**`.trash` が様式として並ぶのを防ぐ。ドットは `is_valid_form_id()` が通さない文字なので、正規の様式IDと衝突しない。

### 画面

- ヘッダーの「保存」の隣に **「この様式を削除」** を置く
- **壊れている様式を選んでいるときも押せる**（それが目的）
- 押すと確認する
  > 「クレーン日常点検表（form_01）」を削除します。
  > ゴミ箱（.trash）に移すので、あとで戻せます。
  > 削除しますか？
- 削除したら一覧を読み直し、開ける様式があればそれを開く。無ければその旨を通知欄に出す

## ④ 1日のマスの位置に実施月

### 何のためか

締め日が24日の場合、1〜8マス目は前の月、9マス目から実施月になる。紙の上で月の変わり目が分からないため、そこに月を印字できるようにする。

### 追加する項目（左の一覧の「共通」）

| 表示名 | 内部の名前 | 印字される場所 |
|---|---|---|
| 実施月（1日のマスの位置） | `meta.month_start` | 日にちが1になるマス |
| 前月（1マス目の位置） | `meta.month_prev` | 1マス目 |

- **`month`（1枚に1か月分）の様式でだけ一覧に出す。**`year` と `single` には1日のマスという概念が無い
- 表示は「**8月**」の形（数字＋「月」）
- 置き方は他の項目と同じ。**最初のマスの上あたりに置けば、アプリが正しいマスまで横にずらす**

### 仕組み

新しい描画処理は作らない。**「マスの数だけ繰り返す」項目として扱い、該当するマスでだけ文字を返す。**

```python
    if source == "meta.month_start":
        d = slot.get("date")
        return f"{d.month}月" if d and d.day == 1 else ""
    if source == "meta.month_prev":
        d = slot.get("date")
        return f"{d.month}月" if d and slot.get("index") == 1 else ""
```

これにより、余りマスの扱い・ページ振り分け・プレビューの仕組みがすべて既存のまま使える。

### スロットに `index` を持たせる

`meta.month_prev` は「1マス目かどうか」を知る必要がある。`build_slots` が作る各スロットに `"index": n` を足す。プレビュー側は `n` を直接持っているのでそのまま使う。

### 月の位置は毎月変わる

| 表示月 | サイクル | 1日のマス |
|---|---|---|
| 2026年8月 | 7/24〜8/23（31日） | 9マス目 |
| 2026年3月 | 2/24〜3/23（28日） | 6マス目 |

自動で追従する。利用者が置き直す必要はない。

## 検証方法

- サーバー側の新しい処理（縦書き・削除API・新項目2つ・`.trash` の除外）に **pytest のテストを追加**し、全件が通ること
- ブラウザで次を実際に行う
  1. ズレを手入力して、薄い文字の並びが動くこと
