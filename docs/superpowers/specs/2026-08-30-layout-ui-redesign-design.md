# 様式レイアウト画面 UI改善 設計書（案A）

**作成日:** 2026-08-30
**状態:** 承認済み（2026-08-30）

## 目的

様式レイアウト画面（`/layout`）を、**配布先の現場担当者が、そばで教えてもらえない状態でも、自力で最後まで設定できる**画面にする。

## 前提

| 項目 | 内容 |
|---|---|
| 操作する人 | 配布先の現場担当者（エンジニアではない） |
| サポート | 受けられない。画面だけで完結する必要がある |
| 紙の様式の形 | 現場ごとにバラバラ（横並び・縦並び・1回1枚が混在） |

## 現状の問題（実際にコードを追って特定したもの）

1. **様式の追加が `prompt()` 6連発。** `month` や `使用前` を手打ちし、機器名をカンマ区切りで正確に写す必要がある。途中で戻れず、キャンセルすると最初から。
2. **「軸」が理解できない。** 「1つ目の欄」「ズレ x:23.0」から何をすべきか読み取れず、正しく指定できたかも試し刷りするまで分からない。
3. **置いた印が点だけ。** 何が印字されるか見えないため、紙に出すまで位置の妥当性を判断できない。
4. **未配置の項目数が保存時にしか分からない。**
5. **試し刷りの前にまた `prompt()`。** `YYYY-MM` を手打ちする。
6. **専門用語がそのまま出ている。** `item:床上操作式クレーン|傷はないか`、`on_axis`、X/Y座標（PDFのYは上が正、という画面と逆の決まりの説明もない）。

さらに重い問題として、**うまくいかないときに理由が画面に出ない**。様式PDFのファイル名が `form.pdf` でないだけで画面が真っ白になる（2026-08-30に実際に発生）。

## 変えないもの

- **`layout.json` の形式。** 既存の様式はそのまま開けて、そのまま出力できる。
- **サーバー側のAPI。** 追加・変更しない。必要な情報はすべて既存のエンドポイントで揃う。
- **基本操作。** 「左で項目を選ぶ → 様式の上をクリックして置く」は維持する。
- ポート5000、様式の保存場所、`form.pdf` / `layout.json` というファイル名。

## 使用する既存API（すべて変更なし）

| API | 用途 |
|---|---|
| `GET /api/forms` | 様式一覧。`has_pdf` `error` `editable` `warning` を状態バッジに使う |
| `GET /api/forms/<id>/layout` | 設定の読み込み |
| `POST /api/forms/<id>/layout` | 保存 |
| `GET /api/forms/<id>/pdf` | 様式PDFの表示 |
| `POST /api/forms` | 様式の新規作成（ウィザードから） |
| `GET /api/forms/<id>/preview` | 試し刷り |
| `GET /api/equipment` | 機器の選択肢、点検項目、`input_type`（数値か判定か） |
| `GET /api/holidays?start=&end=` | 日にちの色（土曜=青／日曜・祝日・休業日=赤） |
| `GET /api/config` | `cycle_start_day`（日付の計算）、`building_info.building_name` |

## 画面設計

### 全体構成

今の1画面（左：項目一覧／中央：PDF／右：設定／下：軸バー）を土台にする。上部ヘッダーに**表示月の選択**を追加する（プレビューと試し刷りの両方で使う）。

```
┌─────────────────────────────────────────────────────┐
│ 様式 [クレーン日常点検表 ▾]  月 [2026-08]  試し刷り  保存 │
├──────────┬────────────────────────┬─────────────────┤
│ 置く項目  │  様式PDF                │ 選んだ項目       │
│ 8/11     │  （印字される文字を      │ 位置・大きさ     │
│ あと3項目 │    そのまま表示）        │ 置き直す・消す   │
├──────────┴────────────────────────┴─────────────────┤
│ 並び方： [1日目のマスを指定] [2日目のマスを指定]  欄の数 31 │
└─────────────────────────────────────────────────────┘
```

### 1. 様式追加ウィザード

`prompt()` 6連発を、画面内モーダルの4手順に置き換える。各手順に「戻る」があり、閉じるときは確認する。

| 手順 | 内容 | 次へ進める条件 |
|---|---|---|
| 1 | **PDFを置く** — ドラッグ＆ドロップまたはファイル選択。読み込めたら1ページ目を表示し、ページ数を出す | PDFが読めている |
| 2 | **形を選ぶ** — 3種類を図で示して選ぶ | 1つ選択 |
| 3 | **機器を選ぶ** — `category_minor` の一覧をチェックボックスで。絞り込み用の入力欄つき | 1つ以上選択 |
| 4 | **名前と点検種別** — 名前（日本語可）とラジオ（使用前／月例） | 名前が空でない |

手順1で弾く条件（その場でメッセージを出す）:

- 拡張子が `.pdf` でない
- 先頭が `%PDF-` でない
- 50MBを超える
- ページ数が0

手順2の選択肢と、それが決めるもの:

| 選択肢の表示 | `period` | 欄の数の既定 |
|---|---|---|
| 1枚に1か月分（日付が横に並ぶ） | `month` | 31 |
| 1枚に1年分（1月〜12月が並ぶ） | `year` | 12 |
| 1回の点検で1枚 | `single` | （軸なし） |

「作成」で `POST /api/forms` に `multipart/form-data` で送る。既存のサーバー実装に合わせ、`targets` は**JSON配列を文字列にしたもの**を渡す（例: `["床上操作式クレーン"]`）。

| 送る項目 | 内容 |
|---|---|
| `form_id` | 自動採番した値（後述） |
| `form_name` | 手順4で入力した名前 |
| `period` | `month` / `year` / `single` |
| `inspection_type` | `使用前` / `月例` |
| `targets` | 選んだ機器名のJSON配列（文字列） |
| `file` | 手順1で選んだPDF |

### 2. 様式IDの自動採番

**利用者に様式IDを入力させない。** ウィザードが自動で決める。

- 形式は `form_01` `form_02` …（2桁ゼロ詰め、99を超えたら `form_100` と桁を増やす）
- `GET /api/forms` の結果を見て、**未使用のいちばん小さい番号**を選ぶ
- 生成した値は `is_valid_form_id()` の規則（半角英数字とアンダースコア・64文字以内・Windows予約名でない）を必ず満たす
- 利用者には様式の**名前**だけを見せる。IDは「フォルダ名: form_01」として一覧と右パネルに小さく添える（フォルダを探すときに必要なため）

これにより、日本語フォルダ名・ハイフン・パス入力といった失敗が原理的に起きなくなる。

### 3. 印字プレビュー（この設計の中心）

中央のPDFの上に、**実際に印字される文字をそのまま重ねて表示する**。点の代わりになる。

各フィールドについて:

1. `on_axis` が真なら n = 1〜欄の数、偽なら n = 1 のみ
2. 位置を計算する（既存のPython実装と同じ式）
   `x = field.x + axis.step_x × (n − 1)` / `y = field.y + axis.step_y × (n − 1)`
3. PDF座標を `viewport.convertToViewportPoint(x, y)` で画面座標に変換する
4. 文字サイズ = `(field.font_size または default_font_size) × viewport.scale`
5. 下表の見本値を描く

| source | 見本として表示する内容 |
|---|---|
| `meta.day` | その欄の日付の「日」。土曜は青丸、日曜・祝日・会社休業日は赤丸で囲む |
| `meta.month` | 選択中の表示月 |
| `meta.year` | 選択中の表示年 |
| `meta.unused` | `✓`（使用せず欄。薄い色で表示する） |
| `meta.inspection_date` | 表示月の1日 |
| `meta.inspector` | `見本 太郎` |
| `meta.department` | `見本部` |
| `meta.building_name` | 設定の建物名 |
| `meta.general_remark` | `見本` |
| `item:機器|項目` | マスタの `input_type` が `数値` なら `0.00`、それ以外は `✓` |
| `remark:機器|項目` | `見本` |

日付は `cycle_start_day` から計算する（表示月の前月の締め日から当月の締め日の前日まで）。土日祝の判定は `/api/holidays` の結果を使う。欄の数が日数を超える余りマスには何も描かない。

**選択中のフィールドは枠で囲んで強調する。**

### 4. 「軸」の言い換えとゴースト表示

用語を変える。

| 今 | 変更後 |
|---|---|
| 軸 | 並び方 |
| 1つ目の欄を指定 | 1日目のマスを指定（`year` 型では「1月目のマスを指定」） |
| 2つ目の欄を指定 | 2日目のマスを指定 |
| ズレ x:23.0 y:0.0 | （数値は表示するが、主役はゴースト表示） |

指定の途中は、画面上部に何をすべきかを常に出す（例：「つぎに、2日目のマスをクリックしてください」）。

**2つ目を指定した瞬間、印字プレビューが欄の数だけ描かれる。**これがそのままゴースト表示になるため、追加の実装は不要。紙のマスと重なっていれば正しく指定できたと目で確認できる。

step_x と step_y が両方0になった場合は、今と同じく警告を出す。

### 5. 残り項目の表示

左パネルの上部に常時表示する。

- `置いた 8 / 11`
- `あと 3 項目`（クリックするとその項目を選択状態にする）

数え方は既存の `countUnplaced()` と同じ。`meta.*` と `remark:` は必須ではないので数に入れない。

### 6. 状態バッジとエラーの可視化

様式の一覧（プルダウン）と、選択時のメッセージで次を知らせる。

| 状態 | 判定方法 | 表示 |
|---|---|---|
| 設定が壊れている | `/api/forms` の `error` が空でない | ⚠ 設定を読めません |
| 様式PDFがない | `has_pdf` が false | ⚠ 様式PDFがありません（`form.pdf` という名前で置いてください） |
| 編集できないフォルダ名 | `editable` が false | ⚠ フォルダ名を直してください（既存の `warning` を表示） |
| 機器名がマスタにない | `targets` と `/api/equipment` の `category_minor` を突き合わせ | ⚠ 「○○」は点検項目マスタにありません |

**画面を開いたとき、壊れた様式を自動で選ばない。**一覧の中で最初の正常な様式を開く。正常な様式が1つも無ければ、その旨と対処を画面中央に出す。

### 7. 試し刷り

`prompt()` をやめ、ヘッダーの表示月の選択をそのまま使う。押すと保存してから別タブで開く。ボタンの近くに「紙に印刷して、元の様式と重ねて確認してください」と添える。

## ファイル構成

`static/layout.js` は現在690行。この設計で1000行を超えるため、ESモジュールとして3つに分ける。

| ファイル | 責任 | 主な外部インターフェース |
|---|---|---|
| `static/layout.js` | 画面の組み立て、状態、様式の選択、保存、項目の配置 | 既存の export を維持 |
| `static/layout-wizard.js` | 追加ウィザード（4手順） | `openWizard(equipment, existingIds)` → 作成された様式IDを返す |
| `static/layout-preview.js` | 印字プレビューとゴースト表示 | `renderPreview(container, layout, viewport, ctx)` |

`layout-preview.js` は `layout.js` の状態に依存させない。必要な材料（layout、viewport、機器マスタ、祝日、表示年月、選択中のフィールド番号）はすべて引数で受け取る。これによりプレビュー単体で動作を確かめられる。

CSSは `static/layout.css` に追記する（ウィザード用とプレビュー用のクラスを追加）。

## サーバー側

**変更なし。**

## エラー処理

| 起きること | 画面の反応 |
|---|---|
| PDFが読めない | ウィザードの手順1でその場でメッセージ。次へ進ませない |
| 作成APIが400を返す | ウィザード内にサーバーのメッセージをそのまま表示。入力は保持する |
| 作成APIが401を返す | 「アプリを動かしているPCで操作してください」と表示 |
| 保存が401 | 現状と同じメッセージ |
| `/api/holidays` が失敗 | 日にちは黒で描く（色だけ諦め、プレビュー自体は出す） |
| `/api/equipment` が失敗 | 判定・数値の区別ができないので、すべて `✓` で描く |
| 様式PDFが表示できない | 中央に理由と対処を出す。配置操作は止める |

プレビューの描画で例外が出ても、配置や保存の操作は止めない。

## 検証方法

- **サーバー側を変更しないので、既存のテスト276件がそのまま通ること。**
- ブラウザで次を通しで実施する。
  1. ウィザードで様式を新規作成する（PDFのドラッグ＆ドロップ、形の選択、機器の選択、名前の入力）
  2. 作られたフォルダが `form_NN` で、`form.pdf` と `layout.json` が揃っていること
  3. 並び方を指定し、ゴーストが紙のマスと重なること
  4. 項目を置き、プレビューに `✓` と日にちが出ること。土曜が青、日曜が赤になること
  5. 「あと N 項目」が減っていくこと
  6. 保存し、試し刷りが出ること
- **既存の `sample_daily` が今までどおり開けること**（後方互換）。
- わざと壊した様式（`form.pdf` が無い／`layout.json` が壊れている／機器名がマスタに無い）を用意し、画面が真っ白にならずに理由が出ること。
